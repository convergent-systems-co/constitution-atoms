# Plan: constitution-atoms v0.1 Bootstrap

**Objective:** Schemas accepted and the convergent-systems-co AI governance constitution expressed entirely via constitution-atoms — one full composition published.

## Rationale

| Alternative | Pros | Cons | Verdict |
|---|---|---|---|
| Replace schemas + add content in one PR | Single atomic change; CI runs once; composition references atoms from same commit | Slightly larger diff | **Chosen** |
| Replace schemas first, add content separately | Smaller diffs | Two PRs; schema PR is untestable without content | Rejected |
| Keep existing schemas, add content only | Less diff | Existing schemas have wrong `type` enum (agent-atoms copy-paste) — atoms would fail validation | Rejected |

## Scope

**Schemas to replace (wrong type enum — copied from agent-atoms):**
- `schemas/atom-v1.json` — rewrite to `charter` / `bylaw` / `principle` / `mission-statement` / `value-declaration` discriminated union
- `schemas/composition-v1.json` — rewrite for `constitution` type; refs use `constitution-atoms://atoms/...` pattern; composition dir is `constitutions/`
- `schemas/rule-v1.json` — rewrite predicate subject_ref pattern to match constitution-atoms atom IDs

**Atoms to create:**
- `atoms/charter/ai-governance.json` — AI governance charter (Constitution.md v0.3)
- `atoms/charter/open-source-commitment.json` — Apache-2.0 / CC-BY-4.0 commitment charter
- `atoms/bylaw/amendment-procedure.json` — governance amendment procedure bylaw

**Composition to create:**
- `constitutions/cs-ai-governance@0.3.0/composition.json` — full CS AI governance constitution assembling the two charters + bylaw

**Exports to update:**
- `exports/catalog.json` — include all 3 atoms + 1 composition

**Validator to verify:**
- `scripts/validate.py` — existing script; verify it handles `constitutions/` dir (currently coded for `agents/`); update if needed

## Approach

1. Rewrite `schemas/atom-v1.json` with correct constitution-atoms types and type-specific fields
2. Rewrite `schemas/composition-v1.json` for constitution composition type
3. Update `scripts/validate.py` to read from `constitutions/` dir instead of `agents/`
4. Create `atoms/charter/ai-governance.json`
5. Create `atoms/charter/open-source-commitment.json`
6. Create `atoms/bylaw/amendment-procedure.json`
7. Create `constitutions/cs-ai-governance@0.3.0/composition.json`
8. Update `exports/catalog.json`
9. Run `python3 scripts/validate.py` to confirm clean pass

## Testing Strategy

- `python3 scripts/validate.py` must exit 0 with all atoms + composition marked valid
- Manual JSON parse of every created file to confirm no syntax errors

## Risk Assessment

| Risk | Mitigation |
|---|---|
| Validator uses `agents/` dir hardcoded | Update COMPOSITIONS_DIR in validate.py to point at `constitutions/` |
| Schema `additionalProperties: false` rejects type-specific payload fields | Use `allOf` + `if/then` conditionals as in agent-atoms pattern |
| composition.json ref pattern must match atom `id` field | Keep IDs as simple slugs matching filename stems; refs use `constitution-atoms://atoms/<type>/<id>` |

## Dependencies

None — self-contained.

## Backward Compatibility

Schemas are v1 replacing a v1 stub; no consumers of the stub exist yet (catalog is empty). No migration required.
